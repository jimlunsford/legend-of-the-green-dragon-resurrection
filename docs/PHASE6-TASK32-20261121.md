## F1: the failed-flee message

A failed flee in a forest fight printed "`` `\$You failed to flee your opponent! ``" in the page's text color.
`lib/forest_combat.php` (since `bc94205`, Phase 3) wrote the message in single quotes, where `\$` stays two
characters; the color code then read `` `\ ``, which `appoencode()` does not know, so it printed it as text and the red
never started. 1.1.2 wrote the same text in double quotes (`forest.php` line 35 at the tag), where `\$` is `$`.

| File | Line | Before | After |
| --- | --- | --- | --- |
| `lib/forest_combat.php` | 187 | ``output('`c`b`\$You failed to flee your opponent!`0`b`c');`` | ``output('`c`b`$You failed to flee your opponent!`0`b`c');`` |

The page now holds `<div class='rz-center'><b><span class='colLtRed'>You failed to flee your opponent!</span></b></div>`,
as 1.1.2 rendered it (sheet 1).

**The sweep.** Every PHP file Git tracks outside `tests/` and `lab/` (361 files: the game's pages, `lib/`, `modules/`,
`src/`, `scripts/` and `upgrades/`), read with PHP's tokenizer: each single-quoted string, with its two real escapes
(`\\` and `\'`) set aside, searched for a backslash before `$`, `"`, `{`, `n`, `r`, `t`, `v`, `e`, an octal digit, `x`
or `u`, the escapes only double quotes have. At `a2b3208` it finds 31 strings, at this commit 30:

| Kind | Strings | Files | Verdict |
| --- | --- | --- | --- |
| The failed-flee message, a color code with `\$` | 1 | `lib/forest_combat.php` line 187 | Fixed (above). The only one of its kind: no other single-quoted string holds a color code with a backslash. |
| PCRE patterns: `\x00`, `\x1F`, `\x7F`, `\r`, `\n`, `\0`, `\$`, `\#` and the like inside a regular expression | 16 | `src/Security/PreferenceState.php` 41, `GameMasterMailSender.php` 21, `MailContent.php` 28, 37, 59 and 60, `NavigationState.php` 40 and 66; `lib/clan_authority.php` 174, `lib/systemmail.php` 79 and 80, `lib/signin_throttle.php` 48, `lib/source_link.php` 19, `lib/account_recovery.php` 89, `lib/account_mail.php` 83, `lib/config_failure.php` 29 | Correct as written: the regular expression engine reads these escapes, and single quotes hand them over unchanged. |
| Character classes for the censor, octal escapes such as `\252` | 14 | `lib/censor.php` 104 to 111, 116 to 118, 120, 121 and 123 | Correct as written: they become part of the censor's regular expression, where PCRE reads the octal escapes (1.1.2 held the raw bytes there). |

No double-quoted string was in scope, and none of the double-quoted color strings near the fixed one (for example
`` output("`\$...") `` in `lib/module_manager.php`, `lib/checkban.php`, `lib/inn/inn_room.php`) is affected: in double
quotes `\$` is `$`.

## F2: abilities need skill as well as uses (recorded, not changed)

**1.1.2's rule.** In each of the three specialty modules at the tag (`modules/specialtydarkarts.php` lines 147 to 169,
`specialtymysticpower.php` 149 to 171, `specialtythiefskills.php` 146 to 168) the `fightnav-specialties` hook offered
level 1 while `uses > 0`, level 2 while `uses > 1`, level 3 while `uses > 2` and level 5 while `uses > 4`, and the
`apply-specialties` hook ran a level while `get_module_pref("uses") >= $l`. Skill only set the day's uses: the new day
gives `(int)(skill / 3)`, plus `specialtybonus` (default 1) for the chosen specialty. So a new character, skill 0, had
one use a day and could spend it on its level 1 ability.

**Resurrection's rule.** An ability of level `l` is offered only while skill and uses are both at least `l`
(`resurrection_combat_forms()`, `lib/specialty_combat.php` line 72, 71 at `a2b3208`), and the round runs only on the
same check under the lock (line 99, 98 at `a2b3208`, the forest; `lib/dragon_combat.php` line 178, the Green
Dragon). With the default bonus the difference shows at skill 0 (one use, nothing to spend it on until the first skill
point, from training's level-up, the Fairy or the Foil Wench); with a larger `specialtybonus` it shows wherever the
bonus gives more uses than the skill.

**Was it on purpose?** It came in with the server-side ability forms in Phase 3, `f882c35` (2026-09-14): the
record says the round "rechecks installed active bundled module, selected identity, strict stored skill/uses"
(`SPECIALTY-AUTHORITY.md` and `CORE-ROUTE-SECURITY.md`, "Forest specialty transaction implementation"), and the
authority tests reject "insufficient skill" for every level (`SPECIALTY-COMBAT-ACCOUNTING.md`, "Independent authority
and module availability"). So the check was written deliberately, as part of the authority. But no record weighs it
against 1.1.2's rule or says why the rule changed, and the same document, a few lines earlier, had said that adding a
stored-skill check "needs explicit tests for the zero-skill daily-bonus case; no implicit rebalance has been made
here" (`SPECIALTY-AUTHORITY.md`, "Combat boundary traced, still BLOCKED"). `CHANGES-FROM-1.1.2.md` had no row.

**Recorded.** `CHANGES-FROM-1.1.2.md`, "Phase 6 task 32", has the row: 1.1.2's rule, the rule now, and why (made in
Phase 3 with the ability forms, never weighed against 1.1.2, found in task 31 and kept for `1.0.0` by Jim's decision
so gameplay does not move at the last step). The behavior is unchanged: no line of the checks changed.
