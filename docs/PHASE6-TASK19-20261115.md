## The check

`tests/browser/tap_targets.py` (with its crawler, `tests/browser/tap-targets.js`). CI has no browser, so it is a local
check, not a test (CLAUDE.md, "No test may skip in CI"); its results are below.

- It copies a tree to a temporary folder, installs it on an empty disposable database with the recommended modules,
  adds three crawl accounts (a superuser, a living player, a dead player; level 5, today's game day) and a little
  content (four mails, a petition, five comments in three places, two news lines), and serves it with `php -S`.
- It crawls every page four roles reach from their start pages: signed out (`home.php`, `create.php`, `about.php`,
  `list.php`, `news.php`, `hof.php`, `referral.php`, `petition.php`, `motd.php`, the forgot-password page), the
  player and the dead player (the village or the shades, and the popups: mail, a read mail, the address book,
  petition, MoTD, a bio), and the superuser (the village, the Grotto, the popups, the petition list and a petition).
  Like task 9's crawl it skips links that would end the session or change the game, and counts one page per script,
  `op` and parameter names. The server lets each crawl request through the game's navigation check for the crawl
  account named in an `X-Crawl-Acct` header, from a prepend file written to the temporary folder, never in the tree.
- On each page, at 390 x 844 (a touch phone) or 1440 x 900, it measures every visible link, button, select, checkbox
  and radio: a checkbox or radio by its largest label that shows (any of its labels toggles it), the control itself
  when none does. Hidden, empty, visually hidden (1 x 1) and off-screen elements are not targets.
- At 390 it fails on any target under 44 x 44 that its exemption list (`EXEMPT`) does not name.
- With `--old-css FILE` it measures each page a second time with that file in place of `assets/ui/resurrection.css`:
  the same response, so only the stylesheet differs. It compares the box of every element on the page, and at 1440
  fails if any moved or changed size.
- It measures a page only once it has settled (layout forced, fonts loaded, two measures 150 ms apart the same), and
  drives the stylesheet swap from the crawler, not from the page: the user editor's "last page hit" is the player's
  stored page shown in a sandbox with scripts off, where no timer or load handler runs (an earlier crawl that waited
  on the page's own callbacks hung there). A page that takes over 120 s is recorded as unmeasured, which fails the
  check, and a crashed page or browser is reopened, so one bad page cannot stop the crawl.

## The fixes

All in `assets/ui/resurrection.css`, inside the phone media query (`max-width: 600px`), by selector, so no page's
markup changes (the about pages' among them):

- `.rz-content td > a, .rz-content li.rz-comment > a, .rz-content a[href^="moderate.php?area="],
  .rz-content a[href^="motd.php"], .rz-content a[data-rz-append], .rz-content a[href^="petition.php?op="]:not(form a),
  .rz-content a[href^="mail.php?op=write"]:has(> img)`: `inline-flex`, at least `--touch-target` (44 px) each way,
  centered, `vertical-align: middle`, as task 18's rule. Task 18's own rule is unchanged.
- The FAQ's contents links: `max-width: calc(100% - 1em)`, so each stays on its bullet's line and its text wraps inside
  the box.
- `.rz-content a.rz-mail-subject`: a full-width flex row, at least 44 px tall.
- `.rz-content li.rz-comment > input[type="checkbox"] + label.rz-sr`: the moderation checkbox's "Select this comment"
  label, read by screen readers only on the desktop, shows on a phone beside its checkbox as a 44 px tall tap target.

`scripts/asset-versions.py --check` passes: no other stylesheet imports `resurrection.css`, and the game versions its
URL by its hash on every request.
