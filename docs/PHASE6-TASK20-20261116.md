## R6: the Dark Horse crash

Jim's evidence: on 2026-11-15 at 14:48:35, 14:48:37 and 14:48:38 UTC, `GET /forest.php` answered 500 three times, right
after he left the Dark Horse Tavern having played both games; the host's nginx error log held PHP fatal errors at
`DarkHorseState.php:50`, and his read-only reproduction gave `Class "Resurrection\Game\StonesState" not found`.

The cause, confirmed locally before the fix: `lib/darkhorse_entry.php`'s exit path (`resurrection_darkhorse_leave()`)
requires `src/Game/DarkHorseState.php` and calls `DarkHorseState::read()`, which checks a finished wager with the
game's own state class (`StonesState` at line 50, `DiceGame` at 56, `FiveSixGame` at 64). Nothing loaded those classes
on that path: the shipped game has no `vendor/`, so no autoloader, and the forest page never required them.

The reproduction, `test_darkhorse_round_trip_back_to_the_forest_after_every_game_http`: with the tavern and its three
games active and `forestchance` at 100, the player searches the forest (GET, then POST), lands in the "cluster of
trees", enters the tavern, asks the old man, plays each game to its end (stones: choose "likepair", bet 10, draw or
settle until complete; dice: bet 10, keep; five-six: roll), leaves (GET, then the POST "Leave the tavern") and opens
`forest.php`. Three rounds cover every wager-state class: dice then stones, five-six, and dice alone. At `c6a89d7`:

```
FAIL: test_darkhorse_round_trip_back_to_the_forest_after_every_game_http

```

Jim's error, exactly. Run alone, a five-six round failed on `FiveSixGame` at line 64 and a dice round on `DiceGame` at
line 56. With the fix the test passes on both legs (below).

## R7: the class loader

`src/autoload.php` is one small PSR-4 loader for `Resurrection\` mapped to `src/`:

- It takes only names under `Resurrection\` whose every segment is `[A-Z][A-Za-z0-9_]*`, so no `..`, slash or lower-case
  file such as `autoload.php` itself can be named, and it loads only a file that exists under `src/`.
- No `vendor/`, no Composer and no other dependency. It registers once (it checks `spl_autoload_functions()`), and its
  functions are declared only if missing, so a second `require` is harmless.
- Its first statement is the S2 guard, like every file under `src/` (`EntryGuardTest`).
- All 65 entry points (every `*.php` in the game's folder and in `scripts/` that defines `RESURRECTION_ENTRY`) require
  it as their second statement, right after `define('RESURRECTION_ENTRY', true)`, so the CLI commands
  (`scripts/install.php`, `scripts/upgrade.php`, `cron.php`) have it too. `tests/bootstrap.php` requires it before
  Composer's autoloader.

The existing requires stay. Each is correct and still loads what its file needs; removing several hundred lines
across the game a step before 1.0.0 would be a large change for no behavior, and the function files they also load
(`lib/array_cursor.php` and the others) are not classes, so no class loader could replace those. The loader is the net
under the requires: a file that forgets one now works instead of crashing.

`tests/unit/AutoloadTest.php` (4 tests):

- every entry point's first two statements are the define and the loader's require, and there are 65 of them;
- each entry point's head alone (its define and require, nothing else), run with `php -n`, registers exactly
  `['resurrection_autoload']` and loads `StonesState`, `DiceGame` and `FiveSixGame`, and not a missing name, without
  touching the database;
- every `Resurrection\` class, interface and enum named in shipped PHP (fully qualified names, `use` imports, qualified
  names, class-name strings, and `new`, `::`, `instanceof`, `extends`, `implements` and `catch` inside namespaced files)
  resolves to the file that declares it, and every type under `src/` sits at its PSR-4 path (more than 40 named, more
  than 45 declared). Checked by mutation: it fails on `\Resurrection\Game\Nope`, the string `'Resurrection\Http\Missing'`
  and a bare `DomainException` inside a namespace;
- the loader refuses other namespaces, lower-case segments, `..` and missing files.

## The logging check

An uncaught error on any page already writes one line with the file and line. `lib/errorhandling.php` turns a warning
into an `ErrorException` that keeps its file and line, nothing in the game turns `log_errors` off, and PHP writes
`PHP Fatal error:  Uncaught <class>: <message> in <file>:<line>`. `FailureLogTest::testAnUncaughtErrorOnAPageWritesALineWithItsFileAndLine`
shows it for a missing class, a warning and a thrown `DomainException` on a probe page that loads the loader and the
error handler (exit 255, nothing on the page, the log's first line ending in the probe's file and line 5). That is how
R6 reached Jim's nginx log.

What logged nothing was a failure the game catches and answers with a 5xx: the player sees "Nothing was changed" (or
the page's own words) with a 500, and the host's log had no line. `test_a_caught_failure_answered_500_leaves_one_log_line_http`
shows one: with a fixture `CHECK` constraint that refuses the tavern exit's write, the POST answers 500 "Tavern exit was
not completed." and, at `c6a89d7`, the server's log gained no line (`AssertionError: 1 != 0`). A static scan of every
shipped PHP file found 43 such paths: 32 `catch (Throwable ...)` blocks that answer `http_response_code(5xx)` and 11
failure helpers (a function that takes the `Throwable` and answers 5xx). Two more catches already logged their own
line.

The fix, `src/Http/FailureLog.php`: `FailureLog::record($error)` writes one line with `error_log()`,
`Resurrection: <page> failed: <class> at <file>:<line>`, the file relative to the game's folder, every character
outside `[A-Za-z0-9_./\-]` replaced. Never the message, the arguments or the trace, which can carry SQL, submitted
values or a token (the model is `pvp.php`'s line since Phase 3). Each of the 43 paths calls it before answering. A
`catch (Throwable)` that had no variable now names one.

`tests/unit/FailureLogTest.php` (4 tests) checks the line (and that a message with SQL and an address stays out), that
`record()` writes exactly one line, the uncaught case above, and that every `catch (Throwable)` or failure helper that
answers 5xx in shipped PHP logs (`FailureLog::record(` or `error_log(`), with more than 30 catches and 10 helpers
found. At `c6a89d7` it listed the 43 silent paths.

## R9: text that is not UTF-8

Jim's evidence: master 5 showed as "Un?lith". The brief named `lib/installer/installer_sqlstatements.php` lines 200, 869
and 765. Every rc.1 database holds the broken bytes.

18 lines in 3 files; no other shipped file. Checked against the historical tag (which never changes): its
`installer_sqlstatements.php` already holds U+FFFD on those lines, so the letters were lost before the preservation
commit; its `prefs.php` holds the Latin-1 bytes `\xe7` and `\xf1` ("Français", "Español"), and its `lib/censor.php` the
same 77 Latin-1 bytes as `main`. The UTF-8 text 1.1.2 meant follows from those bytes and the names: "Unélith" (1.1.2's
Latin-1 `\xe9`), "Français", "Español", and "kyrpä*" (the Finnish word the list carries beside its other Finnish
entries).

The fixes, in the modern tree only:

- `installer_sqlstatements.php` and `prefs.php` carry the UTF-8 text.
- `lib/censor.php` writes each Latin-1 byte as a PCRE octal escape (`\252`, `\300`, ...), so the file is ASCII and the
  patterns are the same bytes: all 184 built patterns, with the escapes mapped back, compare byte for byte with the
  historical ones, and both match the same 194 of 81,696 test strings. One line needed care: the `s` pattern goes into
  a `preg_replace()` replacement, where `\247` reads as back-reference 24, so its backslash is doubled there.
- Upgrade step `upgrades/0003-utf8-seed-text.php`: three `UPDATE`s with literal values, each replacing a value only
  where it equals rc.1's bytes exactly (`CAST(... AS BINARY)`): `masters.creaturename` for `creatureid` 5,
  `settings.value` for `serverlanguages`, `nastywords.words` for `type` 'nasty'. A value an administrator edited is
  left alone, and a rerun changes nothing. The step checks its own literals before it runs. The fresh install records
  it as applied. Its three table sites are added to `docs/RESCAN-TASK3-20261023.md`'s reviewed list. Where the data
  cache is on (off by default), the settings and the word list can show the old text until their cache expires (60 s
  and 600 s).

Tests:

- `test_master_five_reads_unelith_in_the_training_and_the_masters_editor`: a fresh install's master 5 is "Unélith"; the
