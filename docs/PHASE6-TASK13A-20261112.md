## 2. One mail path

- **`resurrection_send_email()` (`lib/systemmail.php`) is the only `mail()` call.** Mail notifications, petition
  notices, the expiration warning and account mail all go through it.
- **The address check.** Recipient and sender must pass `resurrection_mail_address_valid()`: anchored, plain dot-atom,
  at most 128 bytes, no quotes, comments, IP literals, commas or angle brackets.
- **The subject.** A subject with CR, LF or NUL is refused; one outside ASCII goes as one RFC 2047 word.
- **The headers are fixed:**
  - `From`
  - `MIME-Version: 1.0`
  - `Content-Type: text/plain; charset=UTF-8`
  - `Content-Transfer-Encoding: 8bit`
  - `Auto-Submitted: auto-generated`
- **Links in account mail** come from `resurrection_account_mail_link()`, which uses only an `https://`
  `resurrection_server_url()`. Account mail is off in effect without one.
- **F1 fixed.** The expiration warning takes its address from `resurrection_server_url()` only
  (`resurrection_expire_warning_body()`). Without a valid one it says "(Server URL not set or not valid)", and nothing
  is saved. 1.1.2 built a default from `SERVER_NAME` and saved it.
- **Files:** `lib/systemmail.php`, `lib/account_mail.php`, `lib/char_expiration.php`.
- **Tests:**
  - `AccountMailAddressTest::testDotAtomOnly`, `::testRefusesCrLfNulQuotesCommasAndIpLiterals` and
    `::testRefusesOver128Bytes`.
  - `MailMessageTest::testLinksComeFromServerUrlOnly`: forged `HTTP_HOST`, `SERVER_NAME`, `X-Forwarded-Host` and
    `X-Forwarded-Proto`; both links in the body come from `serverurl`.
  - `MailMessageTest::testHttpServerUrlTurnsAccountMailOff`.
  - `MailMessageTest::testFixedSubjectsAndHeaders`: the exact header set as `mail()` handed it to the capture, and the
    RFC 2047 subject.
  - `MailMessageTest::testNoPlayerValueInHeaders`: CR/LF cases, the default sender, and a token scan that finds
    `mail()` called once, in `lib/systemmail.php`.
  - `CharacterDeletionTest::testExpirationWarningLinkComesFromServerUrl`.
  - `test_account_mail_http.py::test_forged_host_never_reaches_a_mail`.

## 3. Tokens and limits

- **Tokens (design 3.2):**
  - 32 bytes from `random_bytes()`, base64url (43 characters); only `hash('sha256')` is stored.
  - The shape is checked before any database work.
  - Each token is bound to its purpose, account, address and `authversion`.
  - Expiry per purpose: `recover` 30 minutes; `verify`, `email` and `mailtest` 24 hours.
  - At most 5 openings, and one use, marked in the transaction that acts on it.
  - A new `recover` token replaces the account's earlier ones.
  - Opening exchanges the token for a 15-minute session grant that holds the hash, never the token.
  - Every function that takes a token, or a mail body that holds one, marks it `#[\SensitiveParameter]`.
- **Limits (design section 5):**
  - One row per limit in `RESURRECTION_ACCOUNT_MAIL_LIMITS`, counted in `account_mail_log` by purpose, account, address
    key (SHA-256 of the lower-cased address) and requester key.
  - The requester key comes from `REMOTE_ADDR` only (the IPv4 address, or the IPv6 /64), never `X-Forwarded-For`.
  - A request is counted whether or not an account matched.
  - The global hourly limit is `account_mail_hourly`. Reaching it writes one game log notice an hour.
- **Cleanup.** The daily maintenance (`lib/newday/newday_runonce.php`) removes tokens older than 7 days and log rows
  older than 30 days. Deleting a character removes its tokens (`lib/charcleanup.php`).
- **Tests:**
  - `MailTokenTest`, ten tests: `testTokenIs43Base64UrlCharactersFrom32Bytes`, `testOnlyTheHashIsStored` (a search of
    every table finds no token, only its hash), `testExpiryPerPurpose`, `testSingleUse`, `testAuthversionChangeKillsIt`,
    `testPurposeAndAddressAreBound`, `testOpenLimit`, `testNewRecoveryTokenReplacesTheOld`,
    `testTheGrantHoldsTheHashAndExpires`, `testCleanupRemovesOldTokensAndLogRows`.
  - `MailLimitTest`: one test per limit row (11), plus `testRequestsAreCountedWhetherOrNotAnAccountMatched` and
    `testTheRequesterKeyIsRemoteAddrOnly`.
  - `SensitiveParameterTest::testEveryParameterThatCarriesTheSecretIsMarked` (the new functions) and
    `::testNoAccountMailFunctionTakesATokenUnmarked`.
  - `CharacterDeletionTest` and `SqlSweepTest`, with reviewed rows added to `RESCAN-TASK3-20261023.md`.

## 4. `account.php`

- **Before anything else.** It defines `RESURRECTION_ENTRY` first, then takes the token out of `$_GET` and `$_REQUEST`,
  and out of every copy of the request address in `$_SERVER`. It sets `REQUEST_URI` and `QUERY_STRING` to the clean
  address, and only then loads `common.php`.
- **`RESURRECTION_SECRET_URL`** (`common.php`) skips the referer record. **`RESURRECTION_NO_KEPT_PAGE`**
  (`lib/pageparts.php`) keeps no page in `accounts_output` and no `restorepage`.
- **Every response** sends `Referrer-Policy: no-referrer`, `Cache-Control: no-store` and `X-Robots-Tag: noindex`.
- **`op=open`:**
  - The requester's opening is counted first; a limited one gets the expired page.
  - It answers GET only.
  - It checks the token (`mailtest` only in this task), stores the grant in a new session id, and answers 303 to
    `account.php?op=confirm` with no body.
- **`op=confirm`:**
  - It shows what the link does.
  - A POST with CSRF confirms in one transaction, uses the token up, clears the grant and rotates the session again.
- **Every other op, refused token or missing grant** gets one fixed page, status 400: "This link has expired or was
  already used. Ask for a new one."
- **Records:**
  - `EntryGuardTest` counts 65 entry points.
  - The route inventory has the rows `account.php`, `?op=open` and `?op=confirm`.
  - `test_operator_pages.py` counts 63 top-level entry files; `account.php` is the 63rd, and without a configuration
    it shows the not-installed page.
- **Tests:**
  - `SecurityHeadersTest::testAccountPageSendsNoReferrerAndNoStoreAndTakesTheTokenOutFirst`.
  - `EntryGuardTest::testEveryEntryPointDefinesTheConstantFirst`.
  - `test_account_mail_http.py::test_every_unusable_link_gets_the_same_page`, with 14 cases, a POST and the limit:
    - no token, an empty one, a short one, a long one, one of the right shape that matches nothing, an array, the
      stored hash in place of the token; a used token, an expired one, one opened five times, one whose account's
      `authversion` moved; no op, another op (`reset`, with a live token), `op=confirm` without a grant;
    - a POST to `op=open` with a live token;
    - the opening limit (30 an hour from one address) reached, with a live token.
    - Each gets the same page, apart from the footer's clock, timings and query count. The tokens of the right shape
      get byte-identical pages. Every opening is counted, none opens a token, and the live link still opens once the
      limit's rows are gone.
  - `test_account_mail_http.py::test_test_mail_round_trip_turns_account_mail_on`: the 303 with an empty body, the
    headers, and the secret search (below).

### Deviations from the design, and why

- **The settings are `account_mail_proof` and `account_mail_pending`, not `account_mail_confirmed`.**
  `settings.setting` holds at most 20 characters. `account_mail_pending` holds the test mail that may be confirmed
  (its token id and the fingerprint it was sent with).
- **The database-backed PHPUnit classes are `Mail*Test`, not the design's `Account*Test`.** PHPUnit runs files in name
  order, and `Account*` ran before `FreshInstallTest` had installed the database (see `CLAUDE.md`, Tests).
  `AccountMailAddressTest` needs no database and keeps its name.
- **`MailCaptureGuardTest` always runs, not only under `RESURRECTION_REQUIRE_PHP=1`.** No local run sends mail either.
