added to its end. `docs/README.md`, the new index, lists every file in `docs/` exactly once, in "Start here",
"Reference" or "Records", and `tests/tooling/test_doc_links.py` holds it to that.

  ignore, never outside the repository, and every heading anchor a link names exists by GitHub's rule (lowercase,
  punctuation dropped, spaces to hyphens, repeats numbered), and HTML `id` and `name` anchors count. `#L10`-style line

  broken reader cannot pass by finding none.

## Found, not changed

Game code, outside this task (no game code changes). Each is a bug fix for a later task, if Jim wants one.

- **F1. The failed-flee message shows a stray "`` `\$ ``".** `lib/forest_combat.php` line 187 prints
  `` '`c`b`\$You failed to flee your opponent!`0`b`c' `` in single quotes, so the backslash stays and the color code
  becomes the unknown code `` `\ ``, which the renderer prints as text: the player sees "`` `\$You failed to flee your
  opponent! ``", without its red. 1.1.2 had the same text in double quotes (`forest.php` line 35 at the tag). Since
  `bc94205` (Phase 3). It is the only single-quoted string with that escape.
- **F2. Abilities need skill as well as uses, and the ledger does not say so.** `resurrection_combat_forms()`
  (`lib/specialty_combat.php` line 71) and the specialty round (line 98) both require skill at least the ability's
  level, as well as that many uses. 1.1.2 asked only for uses (`modules/specialtymysticpower.php` lines 146 to 171 at
  the tag, and the same in the other two specialties): a new character with skill 0 and its one use could cast
  Regeneration. Since `f882c35` (2026-09-14); `SPECIALTY-COMBAT-ACCOUNTING.md` tests "insufficient skill", but
  `CHANGES-FROM-1.1.2.md` has no row for it. Either the ledger gets the row, or the gate goes back to uses only.
- **F3. "1 uses left".** The battle screen's Special Abilities note is `sprintf_translate('%s uses left', ...)`
  (`lib/specialty_combat.php` line 68), so one use reads "1 uses left".
- **F4. The web setup page passes a newer PHP.** `resurrection_setup_preflight()` (`lib/setup/page.php` line 129)
  shows "(8.4 or 8.5 needed)" but marks any PHP from 8.4.0 up as ok, so PHP 8.6 passes, though `composer.json` and the
  documents allow only 8.4 and 8.5. `SUPPORTED-PLATFORMS.md` now says what the check does.
