# Modernization principles

**Preserve the game. Modernize the implementation.**

## Preserve initially

Recognizable gameplay and atmosphere; forest loop; combat semantics; New Day; dragon progression; death/graveyard; economy; races; specialties; hook/event and modular extension contracts; licensed game text; useful administration that can be secured; and the theme/template concept.

Do not rewrite humor, rebalance combat, redesign currency/progression or replace the old interface during characterization. Retain original templates as evidence. No React/Vue/CSS-framework adoption is implied.

## Modernize deliberately

Supported PHP; database transport and SQL parameterization; password hashing/recovery; sessions; CSRF; authorization; contextual output escaping/sanitization; uploads; scheduler; unsafe serialization boundaries; installer; SQL modes; charset; concurrency; non-secret logging; email; deployment/release processes; automated tests.

Use small changes with before/after state evidence. Preserve procedural route/hook contracts initially where practical; extract services only when characterized behavior justifies it. A framework or class conversion is not a goal in itself.

## Defer or replace unless intentionally revived

Historical advertising, old payments, LoGDnet remote behavior, TopWebGames, web PHP evaluator, unsafe source viewing and obsolete endpoints. Keep their original bytes in the historical tag. Main may later remove, isolate or replace them after explicit scope decisions.

## Security and fidelity

Historical defects are not compatibility requirements. Characterization fixtures must label desired behavior, historical defect, obsolete integration or intentional Resurrection correction. No unknown output becomes a golden expectation merely because one run produced it.

Preserve useful native administrative workflows where they can be secured within site/database isolation. Discuss actual workflow tradeoffs instead of imposing maximum restriction without purpose.

## Release gate

Foundation is not alpha or a release. Release only after behavioral, compatibility, security and provenance gates for the shipped scope have passed. Public source and a private unsupported research runtime are different things. No VPS deployment belongs to foundation.
