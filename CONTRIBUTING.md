# Contributing

Resurrection is in foundation / historical characterization, not a released product. Preserve the game while modernizing deliberately.

- Keep original notices, author credits and source provenance. Do not modify the preservation repositories or historical baseline tag.
- Respect the inherited license and noncommercial working position. Do not introduce an incompatible blanket license or copy uncleared modules/assets from another fork.
- Review module dependencies, rights, database effects and security before admission.
- Explain behavior changes and add characterization/regression evidence where behavior matters.
- Do not turn a known security defect into a golden test that blocks a correction.
- Keep changes focused. Avoid broad reformatting, unsolicited framework/UI rewrites and mass replacement of old helpers during foundation.
- Use synthetic fixtures only. Never commit configuration credentials, passwords/hashes, sessions, private mail or raw runtime dumps.
- Run baseline verification, project validation and tooling tests. A successful integrity run is not PHP compatibility or public-hosting approval.

Use ordinary short-lived branches and reviewed commits against main once the repository is published. Historical source and Resurrection release numbering remain separate. See [VERSIONING](docs/VERSIONING.md) and [MODERNIZATION-PRINCIPLES](docs/MODERNIZATION-PRINCIPLES.md).
